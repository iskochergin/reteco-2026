# RETECO_2026

Контекст для Claude Code. Читать перед сессией. Подробности — в `docs/`.

## Задача

SemEval-2027 Task 1 (RETECO), трек 2 (RECOR): разговорный поиск. Дана история
диалога и реплика — найти документы, поддерживающие ответ. Реплики
несамостоятельные, запрос надо восстанавливать из истории. Метрика
**nDCG@10**, макро по 11 доменам. Берём подтреки 2a (поиск), 2b (ответ по
золотым пассажам), 2c (поиск + ответ). Трек 1 не берём.

Две цели: препринт на arXiv до ноября 2026, сабмит 10–31 января 2027.
Исследовательский вопрос — abstention: пара 2b (контекст заведомо достаточен)
против 2c (контекст свой, может не хватать) даёт естественную
неотвечаемость; метка достаточности берётся из qrels.

Сайт: https://datascienceuibk.github.io/RETECO/ · данные: HF
`DataScience-UIBK/RETECO-SemEval2027` · кит: `github.com/DataScienceUIBK/RETECO`

docs/LOG.md           журнал: писать после каждого шага

совпадали.

Установка и команды — в `README.md`.

## Точка отсчёта (dev, 858 реплик)

BM25 на голой реплике **0.1827**, BM25 + история **0.4379** — это бить.
Recall@100 = 0.822: документ почти всегда в первой сотне, рычаг — реранк.

## Лимиты подписки Claude — ЖЁСТКОЕ ПРАВИЛО

- **Массовые LLM-прогоны не через `claude -p` по подписке.** Генерация ответов,
  судья, расширения запросов, LLM-реранк — в Colab-ноутбуках на открытых
  моделях (или по API-ключу, если решит Иван). Подписка — только для работы
  в самой сессии и разовых проверок на 1-5 вызовов.
- Расход смотреть инструментом `get_usage` (строка «Weekly · all models»).
  **Перед началом работы записать текущий процент. Если за работу набежало
  ≥5 процентных пунктов недельного лимита — немедленно остановиться**, ничего
  не запускать дальше и сообщить Ивану с цифрами.
- Перед любым пакетным вызовом `claude -p` (больше 5 вызовов) — оценить
  расход и спросить разрешения. Без разрешения не запускать.
- Длинная сессия сама ест лимит: каждый ход перечитывает весь контекст. При
  контексте больше ~60% — предлагать перейти в новую сессию с промптом.

## Правила

- Обучать и подбирать веса — только на train. **Dev не тюнить.**
- Поиск только по корпусу организаторов, внешние коллекции не подмешивать.
- В поиске не использовать `turns[].answer`, `subquestion_reasoning`,
  `original_query` и будущие реплики. `doc_id` моделям не показывать —
  в 5 доменах он содержит id диалога (docs/data.md).
- **На ноуте ничего не считать.** Всё, что требует модели, GPU или массовых
  LLM-вызовов, оформляется в `colab/*.ipynb`; Иван запускает сам. Локально —
  только писать код и проверять его логику без моделей (секунды, на
  маленьком срезе данных). Ноут — M3 Pro, 18 ГБ, лагает.
- LLM для массовых прогонов — открытые модели в Colab (vLLM). Ридер статьи
  OCC — публичный `occ-ai/OCC-RAG-1.7B`, грузится в Colab без VPN.
  Переписывания dev/train уже сделаны Claude и лежат в `runs/rewrites/`.
- Каждый прогон — `runs/<дата>_<имя>/` с `config.json` рядом.
- После каждого законченного шага — запись в `docs/LOG.md`.
- Вопросы уровня «а стоит ли» — в `docs/NOTES.md`, не решать самому.
- Коммит одной короткой строкой (до ~50 символов), без описания, подписей и
  `Co-Authored-By`. После коммита —
  `git push` в `origin` (github.com/iskochergin/reteco-2026).
- Не плодить файлы. Один скрипт — одна задача.
