# План: лестница подходов

Каждая ступень измеряется на dev против предыдущей одной командой
`score.py --runs runs/<дата>_<имя>`. Обучать и подбирать веса — только на train
(2113 реплик), dev не трогать до финала. Каждая ступень — отдельный прогон в
`runs/` с конфигом рядом.

### Ориентир: Таблица 3 статьи RECOR

nDCG@10, макро по 11 доменам, полный набор (2971 реплика; наш dev — 858 из
них, поэтому числа близкие, но не равные: BM25+History у них .446, у нас .4379).

| ретривер | Base | GPT-4o rewrite | +Reasoning* | **+History** | History+Reasoning* |
|---|---|---|---|---|---|
| DIVER-Retriever-4B | .347 | .430 | .496 | **.545** | .584 |
| ReasonIR-8B | .266 | .357 | .494 | .496 | .552 |
| gte-Qwen | .269 | .345 | .399 | .425 | .461 |
| SFR-Mistral | .240 | .324 | .396 | .429 | .464 |
| BGE-large | .230 | .328 | .347 | .411 | .445 |
| E5-Mistral | .183 | .272 | .352 | .404 | .429 |
| BM25 | .185 | .288 | .360 | .446 | .489 |

\* колонки с Reasoning используют `subquestion_reasoning` — аннотацию, которой
на тесте не будет. Это **oracle-потолок**: знать, что искать, даёт всего +.04
поверх истории. Столько же максимум может дать любое наше сгенерированное
рассуждение (S5).

Три вывода из таблицы:

1. **Rewrite без истории проигрывает истории** (.288 < .446 для BM25). История
   содержит ответы на прошлые реплики, и в них словарь документов. Переписывание
   — компонент, не ступень.
2. **Обычные плотные энкодеры хуже BM25 с историей** (BGE .411, E5 .404 <
   .446). Плотный zero-shot нужен как бейзлайн, не как решение.
3. **Рассуждающие эмбеддеры — главный известный рычаг**: DIVER-4B .545 против
   BM25 .446, zero-shot, без реранка. Это +.10 одной заменой модели.

### Железо

M3 Pro, 18 ГБ RAM, 93 ГБ диска, MPS работает. Модели 4B в bf16 (8 ГБ)
влезают: Diver-Retriever-4B, Qwen3-Embedding-4B, Qwen3-Reranker-4B. Модели
8B (15–16 ГБ: ReasonIR-8B, ReasonEmbed-8B, bge-reasoner-embed) локально не
влезают — Colab или сервер AIRI. Документы короткие (медиана 20 слов), корпус
507 тыс.: сначала замерить скорость на drones (16 тыс. док), потом
экстраполировать. Через AIRI доступны Llama-3.3-70B, **gpt-oss-120b**,
GigaChat — gpt-oss-120b это ровно реранкер из лучшей связки BRIGHT-репродукции.

|---|---|---|
| B0 | BM25, голая реплика | 0.1827, есть |

| B4 | Гибрид RRF(B1, B3) | выше лучшего одиночного; главный вклад — recall@100 |

### Сильные решения (в порядке сборки; в скобках — ожидаемый вклад)

| # | что | почему |
|---|---|---|
| S1 | **Рассуждающий эмбеддер**: Diver-Retriever-4B zero-shot на «реплика + история», RRF с B1. Промпты запроса/документа — как в `retrievers.py` RECOR. (**+.08–.10**) | у авторов .545 против .446; влезает в 18 ГБ |
| S2 | **Cross-encoder реранк топ-100** из S1: Qwen3-Reranker-4B или bge-reranker-v2-m3. Вход — запрос B2 и `content`; **doc_id на вход никогда**. 86 тыс. пар коротких документов на MPS (**+.03–.06**) | recall@100 ≥ .82: документ найден, лежит низко |
| S3 | **Память диалога**: RRF ранжирования реплики с ранжированиями *прошлых* реплик, затухание по расстоянию, вес — на train. Только прошлые реплики (**+.02–.04**) | у 70 % реплик T2+ золото ⊆ золоту прошлых, у 41 % совпадает с предыдущей |
| S4 | **Listwise LLM-реранк топ-20/30**: gpt-oss-120b через AIRI, промпт RankZephyr, окно 20 / шаг 10 — конфигурация лучшей связки BRIGHT-репродукции. 858 реплик — дёшево (**+.03–.05** поверх S2) | на BRIGHT gpt-oss-120b обошёл Qwen3-8B и ReasonRank-32B |
| S5 | **Сгенерированное рассуждение** (HyDE / Query2Doc / BRIGHT-style): LLM пишет, какие документы нужны и гипотетический ответ; текст идёт в BM25 и в S1, RRF (**≤ +.04** — oracle-потолок) | колонка H+R против H в Таблице 3 |
| S6 | **Дообучение на train**: hard negatives из топ-100 S1 → LoRA на реранкер; hold-out **по диалогам**. 8B-эмбеддеры (ReasonIR, ReasonEmbed) — на Colab, если дойдём | 2113 реплик хватает реранкеру, не эмбеддеру |
| S7 | **Ансамбль**: N переписываний + N рассуждений → RRF; выбор эмбеддера по домену (DIVER лучше в 7 из 11, ReasonIR — в law, hardware, drones), выбор только на train | усредняет ошибки одной формулировки; макро-метрика награждает подтягивание слабых доменов |

Ожидаемая финальная связка: S1 → S2 → S3 → S4, с S5–S7 если хватит времени.
Каждая промежуточная тоже сдаётся как бейзлайн в статье. Слабые домены у BM25
на dev — medicalsciences .173, drones .295, politics .322, law .344 — именно
там ReasonIR у авторов сильнее DIVER.

### Что запрещаем себе в поиске

- Не использовать `turns[].answer` — это золотой ответ **текущей** реплики,
  таргет для 2b/2c.
- Не использовать `subquestion_reasoning` и `original_query` до ответа
  организаторов (NOTES.md): это аннотация, а не диалог.
- Не подавать `doc_id` ни в одну модель (утечка id диалога в 5 доменах).
- Не смотреть в будущие реплики диалога.

### Генерация 2b и 2c (главный эксперимент статьи)

Ридер: **OCC-1-1.7B** через `inference.airi.net` плюс Llama-3.3-70B как
контроль. 2b — золотые пассажи; 2c — топ-5 из лучшей ступени. Для каждой
реплики 2c метка достаточности из qrels: попал опорный документ в топ-5.
Судья — своя версия до открытия официальных промптов (NOTES.md).

### Анализ

Разбивка по глубине реплики (T1–T5+: 211/211/211/121/104 реплик dev) и по
доменам; bootstrap-интервалы на всё. Внешние датасеты (QReCC, TopiOCQA, CAsT,
iKAT, BRIGHT, SQuAD 2.0, MuSiQue) — только для обучения компонентов, не в
индекс.


# Литература

Проверено в сентябре 2026.

- `arXiv:2601.05461` **RECOR** (Findings ACL 2026) — сам бенчмарк. Таблица 3:
  DIVER-4B с историей .545 против BM25 .446; GPT-4o rewrite без истории
  .288 — хуже истории. Генерация: Oracle .874 / Retrieved .850 /
  NoRetrieval .816 — **агрегированное 2b-vs-2c у них уже есть**, см. NOTES
- `arXiv:2509.02558` воспроизводимые бейзлайны BRIGHT (SIGIR 2026 Repro):
  лучшая связка Reason-Embed-4B + listwise-реранк gpt-oss-120b, окно 20/шаг 10
- `arXiv:2608.27661` Knowing Before Answering — пробе по скрытым состояниям,
  16 моделей, macro-F1 0.81–0.91; Self-RAG и ChatQA-1.5 около случайности
- `arXiv:2605.28070` Bridging the Detection-to-Abstention Gap — модель
  детектирует нехватку данных, но не отказывается; чинят дообучением
- `arXiv:2607.08456` Two Axes of LLM Abstention — уверенность и отвечаемость
  это разные оси
- `arXiv:2510.01782` Can LLMs Refuse Questions They Do Not Know — метрики
  отказа нестабильны при разной доле отказов, предлагают Refusal Index
- `arXiv:2506.09038` AbstentionBench
- `arXiv:2602.11166` Small Updates, Big Doubts — PEFT поднимает AUROC
  детекторов галлюцинаций

Из этого следует: тезисы «вердикт плохо откалиброван» и «F1 проигрывает
константе» **уже заняты**, на них статью не строим. Строим на переносе с
искусственной неотвечаемости на поисковую.
